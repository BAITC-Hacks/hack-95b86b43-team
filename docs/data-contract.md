# Исполняемый CSV-контракт: этап 1, версия 1.0

Этот документ описывает реализованный формат. `DATA_CONTRACT.md` с подчёркиванием сохраняет предварительные наблюдения об Excel партнёра; адаптеры Excel пока не реализованы. Проверка CSV не подтверждает бизнес-смысл реальных выгрузок автоматически.

## Общие правила

- UTF-8, допускается BOM; разделитель — запятая, экранирование — стандартный CSV. Заголовки регистрозависимы. Неизвестные и повторные столбцы — ошибка.
- Даты строго YYYY-MM-DD. Остатки на начало as_of_date; history_end — предыдущий день; history_start <= history_end.
- Период истории заявляется полным пользователем источника. Импорт не может доказать полноту выгрузки. Нули и пропуски не достраиваются на этом этапе.
- Идентификаторы — непустые строки, ведущие нули сохраняются. Пробелы вокруг значений — ошибка, а не молчаливое исправление.
- Числа в десятичной записи с точкой, без экспоненты/разделителей тысяч, конечные и неотрицательные. В памяти — Decimal. В будущих Python-адаптерах передавать Decimal или строку, не float.
- Количества приведены к base_unit самим адаптером; конверсия метров/бухт/штук не угадывается. Валюта unit_price должна быть единой в наборе; расчётов стоимости пока нет.
- Булевы значения: true / false. lead_time_days — целое >= 0, календарные дни.
- Пустое обязательное значение — ошибка. Необязательное пустое поле становится None, но не нулём.
- source_file и source_row добавляет адаптер, в CSV их передавать нельзя. row — начальная физическая строка CSV-записи, заголовок имеет номер 1. Для многострочных записей сохраняется начальная строка. Ошибки синтаксиса CSV указывают строку обнаружения.
- В customer_anon_id допустимы только заранее обезличенные идентификаторы. Валидатор проверяет наличие, но не может гарантировать обезличенность содержимого. Не передавать ФИО, телефоны или e-mail.

## Файлы и поля

Все девять файлов обязательны, даже если отдельная таблица пуста.

| Файл | Обязательные поля | Необязательные поля |
|---|---|---|
| products.csv | sku, name, category_id, base_unit, active_from | — |
| categories.csv | category_id, category_name | — |
| warehouses.csv | warehouse_id, warehouse_name | — |
| suppliers.csv | supplier_id, supplier_name | — |
| product_suppliers.csv | sku, supplier_id, is_primary, lead_time_days | moq, order_multiple |
| sales.csv | sale_line_id, date, sku, warehouse_id, customer_anon_id, qty, unit_price, operation_type | order_id |
| inventory.csv | snapshot_date, sku, warehouse_id, on_hand, reserved, blocked | availability_start |
| stockouts.csv | sku, warehouse_id, start_date, end_date_exclusive | — |
| inbound.csv | po_line_id, sku, warehouse_id, supplier_id, qty_ordered, qty_received, eta, status | — |

Только sales, stockouts и inbound могут содержать один заголовок без записей. MOQ >= 0, order_multiple > 0; отсутствие этих необязательных параметров не создаёт скрытых значений по умолчанию.

## Семантика

- products.active_from — начало присутствия товара в ассортименте; продажа раньше этой даты блокируется.
- sales.operation_type: sale / return. Количество неотрицательное, знак не кодирует возврат. Возврат не является положительной продажей при проверке stockout.
- inventory определяет текущие пары SKU × склад, включая нулевые остатки. on_hand — физический остаток, reserved и blocked — непересекающиеся части; их сумма <= on_hand. Свободный остаток нельзя передавать как физический с повторным резервированием.
- availability_start — дополнительная дата начала наличия в ассортименте склада, не может быть позже snapshot_date.
- Каждый текущий SKU должен иметь ровно одного основного поставщика. Отсутствие основного поставщика у исторического SKU вне текущего inventory не блокирует загрузку. Несколько основных поставщиков всегда ошибка.
- inbound.qty_received — накопленное полученное количество по строке; <= qty_ordered. Status: confirmed, in_transit, received, cancelled. received требует полного получения. Неполученные confirmed/in_transit с ETA раньше as_of_date дают warning. Отмена не является ожидаемой поставкой.
- stockout — полные календарные дни в полуинтервале [start_date, end_date_exclusive). Конец строго позже начала. Смежные интервалы разрешены, пересекающиеся — нет. Положительная sale внутри интервала — противоречие. Интервал может выходить за период истории; он не обрезается молча.
- Историческая продажа SKU × склад без текущего inventory даёт warning: ассортимент мог быть выведен. Автоматический нулевой остаток не создаётся.

## Ключи и ссылки

Уникальны: sku; category_id; warehouse_id; supplier_id; (sku, supplier_id); sale_line_id; (sku, warehouse_id) в inventory; po_line_id.

Проверяются ссылки на SKU, категории, склады и поставщиков во всех таблицах, где они используются. Пересекающиеся stockout дополнительно выявляют повторные интервалы.

## Результат проверки

ValidationReport: valid, schema_version, as_of_date, row_counts, accepted_row_counts, errors, warnings.

Каждая проблема: code, file, row, field, message. row/field могут быть null для ошибок файла или всего периода. row_counts — число прочитанных строк данных (включая отклонённые), accepted_row_counts — число типизированных строк до проверки связей. При неразбираемом CSV остаток файла может быть непрочитан; весь набор всё равно блокируется.

load_csv_dataset возвращает LoadResult: report и dataset. При любой ошибке dataset=null: никакой частичной активации. Предупреждения не блокируют. Порядок сообщений детерминирован; текущее время не участвует в проверках.

SHORT_HISTORY использует два календарных года по заявленным границам, а не число строк продаж. Оно не оценивает полноту истории конкретного товара.

## Проверяемость будущих MUST HAVE

| Будущий сценарий | Какие входы нужны | Будущая проверка |
|---|---|---|
| Сезонность | Длинная история, категория | Разный прогноз для разных будущих сезонов |
| Устойчивый рост | Последовательность продаж | Рост сохраняется после очистки выбросов |
| Stockout | Продажи и интервалы отсутствия | Отсутствие не трактуется как нулевой спрос |
| Крупный клиентский заказ | customer_anon_id, date, sku, order_id | Дробные строки объединяются в событие |
| Регулярный крупный клиент | Повторяющиеся события | Регулярный спрос не исключается |
| Остаток и путь | inventory, inbound с датами | Частичный приход не учитывается дважды; поздний не скрывает дефицит |
| Группировка поставщиков | product_suppliers, suppliers | Все рекомендации имеют поставщика |

Этап 1 проверяет контракт, а не эти расчёты. Образец из 30 дней не предназначен для обучения сезонности. Адаптер реальных Excel должен явно согласовать недостающие поля и семантику, затем создать тот же InputDataset — ядро переписывать не потребуется.
