# Модель данных

Ниже — целевая логическая схема. Для импорта уже реализован SQLAlchemy Core слой и две миграции Alembic:
`import_batches`, `source_rows`, `source_observations`, `validation_issues`, `dataset_versions`, `dataset_sources`.
Точные количества хранятся как PostgreSQL NUMERIC без заданного масштаба, исходные поля — JSONB,
месяцы развёрнуты в наблюдения со ссылкой на строку. Виды источников и смысл полей разделены,
продажи из перекрывающихся отчётов не суммируются. Каталог и остальные предметные сущности таблицы ниже
ещё предстоит реализовать. Технический ID не заменяет бизнес-ключи и ограничения уникальности.

| Сущность | Основное содержимое и связи |
|---|---|
| User | Идентификатор ответственного, роль; способ аутентификации определяется до публикации |
| Supplier, Warehouse, Category | Справочники; категория имеет подтверждённую расшифровку |
| Product | Код 1С, название, единица хранения, категория |
| SupplierProduct | Product + Supplier, артикул, MOQ, кратность, единица заказа, коэффициент пересчёта, срок поставки; условия версионируются |
| ImportBatch, SourceFile | Контрольная сумма, формат, поставщик, период, охват, статус, путь хранения, автор |
| ValidationIssue | Импорт, лист/строка/поле, серьёзность, причина и решение |
| DatasetVersion | Неизменяемый манифест версий источников и их приоритетов |
| SaleTransaction | Товар, документ, дата, склад, тип движения, количество, анонимный client_id при наличии, источник |
| MonthlySale | Товар, месяц, охват, количество, полнота периода, источник |
| InventorySnapshot | Товар, дата, охват, физический остаток, резерв, свободный остаток, источник |
| InboundShipment | Товар, поставка, количество, единица, ожидаемая дата, склад при наличии, источник |
| StockoutInterval | Товар, охват, начало/конец, основание подтверждения |
| GrowthAssumption, SeasonalProfile | Область действия, период, значение, семантика, источник и версия |
| Job | Вид задания, статус, вход, прогресс, время захвата/сигнала, ошибка, ссылка на результат |
| CalculationRun | DatasetVersion, дата среза, фильтры, параметры политики, версия алгоритма, Job |
| Recommendation | CalculationRun + товар + охват + поставщик; прогноз, запас, путь, количества до/после округления, срочность, ограничения, объяснение |
| Order | Поставщик, номер текущей версии, связь с версиями |
| OrderVersion | Order, версия, статус согласования, автор, время, дата расчёта и полномочия утверждения |
| OrderLine | OrderVersion, Recommendation, рекомендуемое/согласованное количество, единица и причина правки |
| ExportArtifact | OrderVersion, формат, контрольная сумма, файл, автор и время |
| AuditEvent | Пользователь, действие, сущность/версия, время, изменение и причина |

## Инварианты

- Новый импорт не перезаписывает исходные записи предыдущей версии.
- Product ↔ Supplier связываются через SupplierProduct; название папки не заменяет постоянный идентификатор поставщика.
- Продажи по документам и месячные продажи хранятся отдельно. Манифест определяет, какой источник используется на каждом интервале.
- Нормализованные данные и вычисленные результаты не смешиваются в одних полях.
- При экспорте используется сохранённая утверждённая OrderVersion, а не текущие изменяемые справочники.
- Связь рекомендации со входами сохраняется после ручной правки заказа.
- Утверждение проверяет ожидаемую версию заказа и записывает аудит атомарно.
- Статус расчёта «успешно» не означает полноту данных по каждому SKU: ограничения хранятся в строках результата.
- Для денег и точных количеств — PostgreSQL NUMERIC; типы временных рядов в памяти выбираются отдельно при реализации.

Индексы и ограничения уникальности спроектировать после профилирования: прежде всего идентификаторы товаров, товар × дата × охват, документ × товар × источник, расчёт × товар × охват, заказ × версия. Реальные повторные строки документа не удалять без подтверждённого правила дедупликации.
