# План проверки

Реализованы 21 unit-тест нормализации, базового прогноза и расчёта потребности,
а также 14 интеграционных тестов: один файлового сценария и 13 PostgreSQL.
Всего 35 тестов. PostgreSQL-тесты включаются переменной `RUN_POSTGRES_TESTS=1`,
используют отдельную временную схему и не очищают рабочую базу.
Команды находятся в `backend/README.md`. Пять must-have полностью ещё не реализованы;
API, worker и frontend остаются каркасом.

| Расположение | Что проверять |
|---|---|
| `backend/tests/unit/` | Выбросы, stockout, прогноз, округление, запас и сроки на малых контролируемых входах |
| `backend/tests/integration/` | Excel → нормализация → PostgreSQL, API, транзакции утверждения, worker и экспорт |
| `frontend/tests/` | Фильтры, обработка ошибок, правка количества, конфликт версий, доступность действий |
| `tests/acceptance/` | Пять must-have и весь путь менеджера |
| `tests/fixtures/synthetic/` | Воспроизводимые обезличенные сценарии с известным ожидаемым результатом |

## Обязательная приёмка

1. История, остаток, путь, категория и внешний прирост влияют на результат в специально подобранных сценариях. Проверять значение до округления, чтобы MOQ не скрывал эффект.
2. Сезонный ряд даёт сезонный прогноз, устойчивый рост сохраняется, разовый пик не превращается в тренд.
3. Для известных интервалов stockout восстановленный спрос выше сырого. При достаточных запасах финальный заказ может остаться нулевым.
4. Разовая продажа 20× и её разделение по документам одного анонимного клиента не увеличивают регулярный прогноз сверх заданного допуска. Регулярные крупные покупки сохраняются.
5. Группировка по поставщикам, объяснение количества и экспорт совпадают.

Дополнительно: поздняя поставка не закрывает ранний дефицит; нулевая потребность не округляется до MOQ; бухты и метры пересчитываются явно; резерв не вычитается дважды; неизвестные данные не становятся нулями; повторный импорт не удваивает продажи.

## Сценарий пользователя

Загрузить источники → просмотреть проблемы → создать набор данных → выполнить расчёт → открыть SKU → изменить количество с причиной → проверить → утвердить → экспортировать. Попытка экспортировать неутверждённую версию отклоняется. Конкурентная правка обнаруживается. Изменение утверждённого заказа создаёт черновую версию.

## Оценка модели

Ретроспективная проверка с обучением только на прошлом. Сравнение с простым средним и сезонным наивным прогнозом, MAE, WAPE при ненулевом знаменателе, смещение. Будущие коэффициенты и неполные месяцы не должны создавать утечку данных. Эффект на дефицит/запас оценивается при явно заданных предположениях о поставках.

Реальные исходники не копировать в тестовые fixtures. Интеграционный тест читает их на исходных
местах и проверяет неизменность SHA-256, повторяемость результата и арифметику объяснений.
Он пропускается при отсутствии папки с исходниками. Полноценный синтетический набор ещё предстоит
создать с описанием генерации и фиксированным seed. Текущий файл политики содержит только
явные демонстрационные допущения; он не означает прохождение пяти must-have.
