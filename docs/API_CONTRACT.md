# Контракт API

Предлагаемый REST API, базовый префикс `/api/v1`. Маршруты и схемы ещё не реализованы. После реализации OpenAPI генерируется FastAPI; этот файл фиксирует назначение сценариев.

| Метод и маршрут | Назначение |
|---|---|
| `GET /health` | Проверка доступности сервиса без конфиденциальных данных |
| `POST /imports` | Загрузка файла и метаданных источника; возвращает 202, import_id и job_id |
| `GET /imports` | История загрузок и состояние |
| `GET /imports/{id}` | Покрытие источника и результаты распознавания |
| `GET /imports/{id}/issues` | Ошибки и предупреждения с пагинацией |
| `POST /datasets` | Создание неизменяемого набора из проверенных импортов и явно выбранных приоритетов |
| `GET /datasets/{id}` | Манифест входов, дата/охват, ограничения |
| `GET /catalog/products` | Поиск и фильтрация товаров |
| `GET /catalog/suppliers` | Справочник поставщиков |
| `GET /catalog/warehouses` | Склады и доступные контуры расчёта |
| `GET /catalog/categories` | Категории и их расшифровка при наличии |
| `GET /catalog/policies` | Версии сроков, MOQ, кратностей и правил запаса |
| `POST /catalog/policies` | Создание версии условий с автором и причиной |
| `POST /calculations` | Набор данных, дата среза, область расчёта, параметры и версии политик; ответ 202, calculation_id и job_id |
| `GET /jobs/{id}` | Статус, прогресс, безопасное описание ошибки и ссылка на результат |
| `GET /calculations/{id}` | Параметры и общие ограничения расчёта |
| `GET /calculations/{id}/recommendations` | Рекомендации, фильтры по поставщику/категории/срочности, пагинация |
| `GET /calculations/{id}/recommendations/{recommendation_id}` | История SKU, прогноз, числовое объяснение и источники |
| `POST /orders` | Черновик для одного поставщика из выбранных рекомендаций |
| `GET /orders` | Список заказов с фильтрами |
| `GET /orders/{id}` | Текущая версия, строки, правки и статус |
| `PATCH /orders/{id}/lines/{line_id}` | Согласованное количество, причина, ожидаемая версия; при необходимости создаёт новый черновик |
| `POST /orders/{id}/review` | Фиксация проверки текущей версии |
| `POST /orders/{id}/approve` | Утверждение проверенной версии уполномоченным пользователем |
| `POST /orders/{id}/exports` | Задание экспорта утверждённой версии, формат XLSX/CSV; ответ 202 и job_id |
| `GET /exports/{id}/download` | Получение файла после проверки доступа |

## Общие соглашения

В ответе списка: items, page, page_size, total. Ошибка: code, message, details, request_id. Никаких трассировок, секретов и сырых строк продаж в публичных ошибках.

Числовой результат рекомендации содержит forecast_demand, safety_stock, available_stock, eligible_inbound, raw_requirement, order_quantity, order_unit, rounding_adjustment, urgency, explanation_steps, data_limitations. Фактические названия и типы закрепить в Pydantic-схемах при реализации. Точные десятичные значения передавать в согласованном формате без потери точности.

Отсутствующее значение передаётся как null с причиной, а не как 0. Неопределённая рекомендация не может выглядеть как обоснованный нулевой заказ.

Создание расчётов, заказов, утверждений и экспортов предусматривает ключ идемпотентности. Повтор запроса не создаёт вторую операцию. Изменение заказа требует expected_version; несовпадение — 409. Ошибка входов — 422, отсутствие полномочий — 403, неизвестный ресурс — 404. Доступ проверяется на сервере независимо от скрытых кнопок в интерфейсе.

Метода отправки поставщику нет. Frontend никогда не пересчитывает утверждённое количество самостоятельно.
