# Критерии приёмки HACKALEM AI

Этот документ связывает требования кейса с наблюдаемым поведением. Наличие строки в чеклисте не означает автоматически пройденный тест. Для сдачи сохранить результат запуска тестов, сборки интерфейса и ручного сценария на текущей версии кода.

## Обязательные возможности

| Требование | Проверка | Признак корректности |
|---|---|---|
| История продаж | Рассчитать стабильный контролируемый ряд | Базовый уровень соответствует регулярным продажам, нули при наличии не отброшены |
| Текущий остаток | Увеличить свободный запас при неизменных прочих входах | Неокруглённая потребность не увеличивается; резерв и блокировка вычтены ровно один раз |
| Товары в пути | Сравнить своевременную, позднюю, просроченную и частично полученную поставки | Учтён только неполученный объём в допустимом статусе и горизонте; просроченный ETA не превращается в приход сегодня |
| Категория | Проверить товар с недостаточной собственной сезонной историей | Источник сезонного профиля виден; товары разных единиц не суммируются в абсолютных величинах |
| Сезонность | Контролируемая повторяющаяся сезонная история | Прогноз меняется по будущим датам; годовой рост не выдаётся за сезонность |
| Устойчивый рост | Сравнить постоянный и устойчиво растущий ряд | Рост влияет на будущий спрос; пределы экстраполяции видны |
| Stockout | Исключить известные дни наличия и восстановить скрытый спрос | Дни отсутствия не становятся обычными нулевыми наблюдениями; доноры только из прошлого |
| Разовые крупные заказы | Добавить большую покупку одному клиенту и раздробленный вариант | Исходные строки сохранены; регулярный baseline не включает исключённую партию |
| Регулярный крупный клиент | Ежемесячные сопоставимые покупки и повтор после первого исключения | Регулярные последующие события сохраняются; история не переписывается будущим знанием |
| Заказы по поставщикам | Рассчитать выбранный склад/категорию | Есть артикул, поставщик, количество, срочность и числовое обоснование |
| Решение менеджера | Правка с причиной → утверждение → CSV | Рекомендация и решение различимы; CSV соответствует утверждённой версии |

Для проверки влияния факторов сравнивать также значения **до** MOQ и округления: упаковка может скрывать небольшую разницу.

## Числовые и календарные проверки

1. Доступный запас равен физическому минус непересекающиеся резерв и блокировка.
2. Горизонт равен сроку поставки плюс интервалу пересмотра; в объяснении указана принятая трактовка границ дат.
3. Спрос за горизонт — сумма дневного прогноза, а не месячное значение без приведения единиц.
4. Поставка после горизонта не уменьшает текущую потребность.
5. Полученная часть уже отражена в снимке остатка; она не добавляется повторно.
6. Поставка внутри горизонта не закрывает дефицит, возникший до её ETA.
7. При lost-sales сценарии физический прогноз остатка не отрицателен, а неудовлетворённый спрос показывается отдельно. Бэклог нельзя молча предполагать.
8. Если неокруглённая потребность равна нулю, MOQ не создаёт заказ.
9. Дробные метры и артикулы с ведущими нулями сохраняются до экспорта.
10. Итог объяснения совпадает с рекомендованным количеством; правка менеджера не маскируется под расчёт алгоритма.

## Защита данных и воспроизводимость

- CSV с ошибками не допускается в расчёт и не заменяет рабочий набор.
- Ошибка содержит файл, строку и поле; плохие строки не пропадают молча.
- Скрытая истина `metadata/true_demand.csv` не входит в `InputDataset`.
- Повторная подготовка одинакового среза даёт одинаковый результат.
- Новые продажи после даты среза не меняют ранее рассчитанный baseline.
- Исходные продажи, исключения и оценки stockout доступны для аудита.
- Только обезличенный клиентский идентификатор; поля ФИО/телефон/почта не входят в контракт.
- Нет вызова отправки заказа поставщику.
- Неизвестные данные сопровождаются ограничением; их нельзя выдавать за достоверный ноль.

## Команды проверки

Из корня проекта в PowerShell. На данной машине готовое окружение — `.venv-win`; если установлено другое стандартное Windows-окружение, замените путь интерпретатора.

```powershell
.\.venv-win\Scripts\python.exe -m pytest -q
.\.venv-win\Scripts\python.exe -m backend.validate_data --input data/samples/minimal --as-of-date 2026-09-01 --history-start 2026-08-02 --history-end 2026-08-31
.\.venv-win\Scripts\python.exe -m backend.validate_data --input data/synthetic --as-of-date 2026-09-01 --history-start 2024-09-01 --history-end 2026-08-31
.\.venv-win\Scripts\python.exe -m pip check
.\start.ps1
```

Для отсутствующего большого набора сначала выполнить:

```powershell
.\.venv-win\Scripts\python.exe -m backend.generate_synthetic --output data/synthetic --seed 42
```

В другом терминале:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

`SHORT_HISTORY` на минимальном наборе и `OVERDUE_INBOUND` на полной синтетике ожидаемы. Они не блокируют набор и должны быть видимы пользователю.

## Ручная проверка перед сдачей

- [ ] Главная страница показывает интерфейс без пустого экрана и ошибок загрузки.
- [ ] Ясно обозначены синтетический источник и дата 01.09.2026.
- [ ] Фильтры склада, категории, поиска и срочности работают совместно.
- [ ] Запуск расчёта показывает состояние загрузки и понятное сообщение об ошибке при сбое.
- [ ] Открывается карточка позиции с историей, прогнозом, поставками и объяснением.
- [ ] Суммы и единицы на графике и в таблице согласованы; разные единицы не суммируются в бессмысленный общий объём.
- [ ] Сценарное изменение спроса пересчитывает результат, не изменяя уже утверждённый заказ.
- [ ] Список/группировка поставщиков соответствует строкам рекомендации.
- [ ] Корректировка количества с причиной сохраняется после повторного открытия.
- [ ] Нельзя выдать неутверждённую версию за утверждённый экспорт.
- [ ] Скачанный CSV содержит утверждённые количества и сохраняет артикулы.
- [ ] Повторное нажатие утверждения не создаёт дубликаты или лишнюю версию.
- [ ] Перезапуск сервера не теряет сохранённое решение менеджера.
- [ ] Интерфейс читается при ширине 1280 пикселей и не обрезает критичные действия на узком экране.
- [ ] Демо проходит без сети после установки зависимостей и сборки интерфейса.

## Как трактовать результаты

Зелёные модульные тесты доказывают проверенные свойства на заданных входах. Они не являются оценкой коммерческой точности или экономии партнёра. Синтетический генератор использует контролируемые поступления для создания сценариев, поэтому на нём нельзя заявлять доказанное сокращение реальных запасов.

На реальных данных следующая проверка — ретроспективное сравнение с простым средним и сезонным базовым методом, только на доступном прошлом. Дни отсутствия не дают наблюдаемого эталона истинного спроса. Для разреженных продаж использовать MAE и агрегированный WAPE при ненулевом знаменателе; процентная ошибка по нулевым продажам не подходит.
